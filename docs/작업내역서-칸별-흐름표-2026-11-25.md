# 작업 내역서 칸별 흐름표 (2026-11-25)

사장님: "기능은 입력하고 끝이 아니라 모든 기능이 연결되게 체계적으로". 그 기준으로 작업 내역서의 칸 하나하나가 **어디에 저장되고, 어디에 보이고, 어떤 기능이 읽는지**를 따라가 끊긴 곳을 이었다.

저장은 전부 작업 내역서 JSON 한 벌 → `appointments.memo` 와 `services.memo` 양쪽(완료 처리 때). 아래 표의 ✓ 는 코드로 확인한 것, **고침** 은 오늘 끊겨 있어 이은 것.

| 칸 | 저장 | 보이는 곳 | 읽는 기능 | 상태 |
|---|---|---|---|---|
| 차량번호 | JSON car_number · 보증서 car_number · **차량 표 plate** | 고객 상세 차량 카드, 보증서 창·PDF, 회원 페이지 증명서 | 다음 작업 내역서 미리 채움 | **고침**: 예약에 차가 안 묶이면 안 들어갔음 → 대표 차에. 기존 1대 보정 |
| 금액 | `services.amount` · 보증서 price | 고객 상세 시공 이력·총 매출, 딜러 카드(미수) | 월말 숫자, 딜러 정산, 회원 등록 조건 | ✓. **고침**: 다시 완료 처리 때 보증서 price 비어 있으면 보충 |
| 메인터넌스 기간 | JSON maintenance_years · 보증서 warranty_period | 보증서, 회원 페이지 "N년 동안 6개월마다" | 메인터넌스 반복 한계(scheduleNextMaintenance) | ✓ |
| 보증서 발행 유무 | warranty_issued | 회원 페이지 증명서 | — | ✓ 완료 처리가 항상 true 로 둠(체크는 사실상 표시용) |
| CRM 기재 유무 | crm_recorded | PDF 체크 표시 | 없음 | **고침**: 완료 처리 때 자동 true. 읽는 기능은 없음 — 없애도 되는 칸 |
| 썬팅 브랜드·제품·농도 | JSON tinting | 증명서 썬팅 줄(농도 포함), PDF | 빠진 칸 검사(농도), 관리 안내(썬팅) | ✓ |
| PPF 범위 | JSON ppf | 증명서, service_area | QC 생성(hasPpf), 시공기 폼 범위, 관리 안내 | ✓ |
| **PPF 제품** | JSON ppf_product(신설) | 증명서 제품 줄, film_used, PDF 제품 줄 | 빠진 칸 검사, 시공기 폼 제품, 회원 페이지 제품 | **고침**: 자유 글자(기타)에서 숫자 찾던 것 → 선택 칸. 옛 기록은 그대로 읽힘 |
| PPF 기타 | JSON ppf_etc | 증명서 범위 뒤 글자, PDF | 옛 기록 제품 인식(폴백) | ✓ 메모로만 |
| **컬러PPF 범위·기타**(신설) | JSON color_ppf/color_ppf_etc | 증명서 컬러PPF 줄(제품 = 기타에 적은 제품명, 없으면 PWF), PDF, service_area·film_used | QC 생성, 시공기 폼 범위·제품, 관리 안내(컬러PPF) | **신설**: 사장님 "컬러PPF·랩핑 제품은 선택 말고 기타에 내가 기입" |
| **썬팅 기타 필름**(신설 11-26) | JSON tint_other{name,density} | 증명서 썬팅 줄 끝에 "제품명 (농도)", PDF 기타 필름 행 | 관리 안내(썬팅) | **신설**: 네 브랜드에 없는 필름을 받아와 시공한 경우 |
| **기타 시공**(신설 11-26) | JSON other_work | 증명서 '기타' 항목, PDF 기타 시공 행, service_area | — | **신설**: 윈드쉴드 보호필름 등. QC·제품 줄 없음 |
| 랩핑 범위·기타 | JSON wrapping/wrapping_etc | 증명서(PWF 면 컬러PPF 줄), service_area | QC 생성 | **고침**: 신차패키지 안의 PWF 가 QC 대상에서 빠졌음 → 랩핑 칸의 PWF/컬러PPF 글자도 봄 |
| 코팅·전장·광택·패키지 | JSON coating/electrical/polish/package_options | 증명서 항목, service_area | 관리 안내(유리막 등) | ✓ |
| 특이사항 및 비고 | JSON notes | PDF, **고객 상세 시공 이력(신설)** | 시공기 폼 참고 메모 | ✓ |
| 작업 사진 | JSON photos | 회원 페이지 증명서 아래, 딜러 현황 페이지, **고객 상세 시공 이력(신설)** | — | ✓ |
| 현장 메모 | JSON field_note | **고객 상세 시공 이력(신설)** | 시공기 폼 현장 메모 맨 앞 | ✓ |

## 완료 처리가 일으키는 일 (순서)
1. 빠진 칸 한 번 묻기(차량번호·금액·PPF 제품·썬팅 농도) → 2. 보증서 채움(처음이면 전부, 다시면 빈칸만) → 3. 시공 기록 생성 또는 같은 날·같은 종류면 갱신(film_used·service_area·amount·memo) → 4. 차량번호를 차에 → 5. QC(PPF·컬러PPF)·메인터넌스·후기요청 생성(이미 있으면 건너뜀) → 6. 예약 완료 + memo 보존 → 7. 회원 페이지 링크 문자 제안 → 8. 딜러 차면 출고 문자 제안(현황 링크 포함) → 9. 소개 포인트.

## 남은 것(결정 필요)
- "CRM 기재 유무" 칸은 읽는 곳이 없다. 없애도 된다.
- 다시 완료 처리할 때 보증서 work_details(항목 글자)는 처음 것이 남는다(증명서 항목은 JSON 에서 새로 만들어 보여 주므로 화면은 맞음).
