# 시공기 파이프라인 재설계 (2026-11-20, 사장님 "근본적인 문제부터 다 해결하자, 싹 갈아엎더라도")

## 왜 이상한가 (진단)
1. 글이 "일을 한 사람의 이야기"가 아니라 "들어온 자료의 받아쓰기"다. 사진 설명·조사 주의점·차별점 목록·사장님 글이 전부 한 프롬프트에 들어가고, 모델은 들어온 것을 다 다루려 한다 → 붉은색 스퀴지, 비금속 필름, 실내 PPF, 한 사람이 책임.
2. 이 차에서 있었던 일(사실)은 열 개쯤인데 2,500자를 써야 한다 → 빈자리를 원리 설명·사진 묘사로 메운다.
3. 검사 → 고치기 → 늘리기 → 또 고치기. 세 번 기운 글. 검사는 정규식이라 아는 헛소리만 잡는다.
4. 금지 수십 개의 프롬프트. 방어적인 글은 일반론으로 흐른다.
5. 모델이 두 세대 전(opus-4-6) → 2026-11-20 Fable 5.2 로 교체 완료.

## 새 구조 — "사실표"가 가운데에 있다
```
접수 ──▶ 조사(구조·사장님 글·사진·타 매장 주의점) ──▶ ★사실표 만들기 ──▶ 사장님 확인 ──▶ 작성(한 번에) ──▶ 검수(표시만) ──▶ 채널·영상
```
- **접수**: 지금 폼/채팅 그대로 + "현장 메모" 한 칸(이 차에서 시간이 간 곳, 손님이 물은 것, 발견한 것. 음성 메모 받아 적어도 됨). 비워도 됨.
- **조사**: 지금처럼 모은다. 단 결과는 글에 바로 들어가지 않는다. 사실표 재료일 뿐.
- **★사실표(facts.ts, Fable)**: 10~15줄. 한 줄 = 한 사실 + 출처 꼬리표(요청 / 사장님 메모 / 사진 / 사장님 글 / 조사 / 매장 기본). 규칙: **이 차·이 의뢰에 대해 참인 것만**. 사진·조사에 보이지만 요청 범위에 없는 것은 사실표가 아니라 "확인 필요" 목록으로. 제품 스펙은 팩트 표·사장님 글에 있는 것만. 차체 형상은 조사에서 확인된 것만. 맡겨야 하는 이유 2~3줄(매장 기본 사실에서 이 글에 맞는 것)도 여기 들어간다.
- **사장님 확인**: 사실표 + 확인 필요 목록을 블로그 탭 작업 카드와 푸시로 보여 준다. 줄을 지우거나 보태고 "이대로 써". (결정 필요: 확인 전까지 기다릴지, 바로 쓰고 사실표는 참고로만 보여 줄지)
- **작성(한 번, Fable 5.2)**: 들어가는 것은 ① 확정 사실표 ② 사장님 글 2편(말투) + 어휘 ③ 글 조건(2,500자·제목·해시태그·줄바꿈·연락처·관리 안내) ④ 이전 글 제목·첫 줄 8편. **사진 설명·조사 원문·차별점 목록·부위 기준 사전은 들어가지 않는다.** 지시: 사실표에 없는 사실은 한 줄도 쓰지 않는다 / 사실표의 각 줄을 적어도 한 번 다룬다 / 사실이 적으면 각 사실을 "왜 그렇게 했는지"로 깊게, 원리 설명으로 메우지 않는다.
- **검수(표시만)**: 사실 금지 검사(열·오버랩·작업자·따옴표·경력)와 팩트체크, 그리고 새로 **사실표 밖 숫자·제품명·부위 검출**. 자동 고치기는 금지 문장 삭제 1회만. 분량·늘리기 패스 없음 — 모자라면 "사실 N줄 더 주시면 채웁니다"로 표시.
- **채널·영상**: 그대로.

## 지우는 것
- 늘리기 패스(expandDraft), 고치기 2회 → 삭제 1회
- 작성 프롬프트의 [부위별 작업 기준]·[프로이즘에 맡겨야 하는 이유] 블록(사실표 재료로만), 사진 장면 블록, 조사 원문 블록
- 사진 읽기의 장면 서술은 "어느 부위, 무슨 단계"만 (도구·색·상표 없음) — 이미 반영

## 남기는 것
- 조사 단계 전체(구조·사장님 글·사진·타 매장 주의점), 사실 금지 규칙, 팩트체크, 2,500자, 제목 키워드, 사장님 글 3편 말투 참고(→ 2편), 영상·채널, 덮어쓰기 규칙

- 폼: "현장 메모" 칸(BlogRequest.notes 재활용)
